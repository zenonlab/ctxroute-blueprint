# ADR-0036 — Static site and bounded local bridge

- Status: accepted
- Date: 2026-09-06

## Context

TobiRink needs a public catalogue surface and connected private views without
turning the browser extension's IndexedDB into a web-readable database.

## Decision

Build the site with Next App Router in static-export mode. The Worker serves
the generated assets, applies an explicit fallback for known public routes,
and keeps API routes separate from the export. The site exposes only `/`,
`/library`, `/library/[workId]`, `/agenda`, `/privacy`, and a dedicated
download page. There is no account, authentication, web settings, Review
route, radio route, or browser storage access.

Le site et les autres workspaces utilisent le baseline TypeScript 7.0.2 fourni
par la racine et vérifié par `npm ls`. Le build Next 16.3.4 reste strict, sans
`ignoreBuildErrors`; son typecheck et son export de production font partie du
gate complet.

Connected local views use `WebBridgePort` protocol v2. Its versioned messages
require the exact TobiRink origin, a handshake whose nonce is generated by the
extension, a 60-second session, a unique request id, strict request/response
correlation, a 64 KiB UTF-8 limit in both directions, and strict Zod validation.
The extension purges expired nonces before every accepted message, retains at
most 32 sessions in least-recently-used order, 64 request ids per session and
512 request ids across the runtime. A quota closes or evicts a session, which
must perform a new handshake. Unknown sessions, altered expirations and replayed
request ids remain rejected. Only bounded bootstrap, paginated
library/search/facet, agenda, and Review snapshots are readable; the sole
write is the atomic `review.decision.write` command. The site receives
serializable projections and never forwards them to the Worker.

`bootstrap.read` exposes only Library and Review counts. `library.read` reads
the complete local membership in transactions of at most 100 works, applies
accent-insensitive search, facets and cursor before returning at most 24 items.
The membership is captured before the traversal; concurrent additions appear
on the next refresh. The visible Library refreshes every 15 seconds, with one
request in flight and stale responses discarded on query changes.
`agenda.read` is the sole
Agenda projection and accepts exactly one date-only Monday-to-Monday half-open
week; it reads at most 100 dated entries. Both projections retain only locally
available progress, favorite-source, release-label, availability and HTTP(S)
URL fields, and shorten their item arrays before the transport limit.

The static app owns one client-side provider for the session. It waits 1.5
seconds for initial detection, validates the correlated transport envelope and
the operation-specific projection before rendering, and schedules expiry from
the extension-issued timestamp. One automatic reconnection is allowed; a
second loss becomes a recoverable error requiring an explicit retry. Global
search navigates to the URL-addressable Library query, while the bounded Review
snapshot feeds the Workbench bell and its existing decision command.

The web workspace pins Vitest 4.1.11, Testing Library 16.3.3, jsdom 30.0.1
and Playwright 1.63.0 as development-only verification dependencies. Vitest
checks schema-gated bridge states; Playwright drives the exported site at the
desktop and mobile reference viewports through a bounded local static server.
Chromium is installed explicitly and is never part of the release artifact.
This version is newer than the fixed boundary for GHSA-7mvr-c777-76hp; both
the complete development graph and the shipped dependency graph must pass the
repository audit without a high-severity finding.

Extension release version `1.0.0` is owned by the extension package manifest.
WXT and the web download surface read that source, while the deterministic
packager uses it for both archive names and verifies the exact production
origin in the generated manifests. The download surface keeps links absent
until a separately approved upload has been verified.

## Consequences

The public site remains cacheable and deployable independently from the
extension. Protocol v1 is intentionally incompatible. A missing extension or invalid handshake produces an installation
or reconnection state, never fabricated private data. Chrome uses
`externally_connectable`; Firefox uses a content script restricted to the
exact site origin.
