# Browser support evidence

Date: 2026-09-08

## Support target

Tobirink targets current stable Chromium and Firefox with separate WXT
Manifest V3 builds. Both packages contain the popup, options, library, Review
and agenda surfaces.

## Generated platform differences

| Capability | Chromium package | Firefox package |
| --- | --- | --- |
| Background | module `service_worker` | module `scripts` entry |
| Popup | `action.default_popup` | `action.default_popup` |
| Settings | `options_ui.open_in_tab` | `options_ui.open_in_tab` |
| Signing metadata | store-assigned ID | stable Gecko ID `tobirink@tobirink.local` |
| Data declaration | exact provider origins and configured site origin | same origins and `required: [bookmarksInfo]` |
| Storage access | native trusted-context restriction; Chrome 140 minimum | application boundary when native restriction is unavailable |

These differences are generated by WXT from one source configuration. Product
components do not branch on a browser name.

## Verified in this environment

- `npm run build:extension` and `npm run build:extension:firefox` generate all
  six declared entrypoints for both targets.
- `npm run test:security` validates both generated manifests, their extension
  CSP, exact origin allowlist and Firefox metadata.
- The extension suite passes 112 Vitest integration, contract and vertical-flow
  tests across 24 files. Despite the historical `test:e2e` script name, it does
  not launch a browser and is not evidence of an installed-extension journey.
- Chromium 153 loaded the extracted Chrome candidate ZIP in an isolated profile:
  health, ordinary-link exclusion, retryable provider outage, zero imported
  Review rows and private status UI passed.
- Firefox 151 loaded the Firefox candidate ZIP temporarily through Marionette:
  health, exclusion of the synthetic ordinary bookmark, empty queue and zero
  imported Review rows passed. Its default bookmarks are preserved; the test
  checks the synthetic source by bookmark ID rather than assuming an empty tree.
- `node scripts/release/package-extension.mjs --verify-isolated` built each
  target twice in fresh directories. Both 20-file archives matched byte-for-byte;
  the ignored verification manifest retains SHA-256 values and paths.
- IndexedDB contracts and additive migrations, including interrupted import
  rollback and Review pagination, pass in Chromium and Firefox 151.

## External browser pass still required

No complete manual compatibility claim is made. The installed test browsers
provide the automated journeys above; they do not establish every journey in
current stable releases. The optional `web-ext` validator is not installed.

The release gate remains open while the real FavLib oracle is unavailable and
the full repository verification fails on the pre-existing Codex MCP config.
The installed checks above do not imply that every interactive journey below
has been completed.

Before release, run the packaged extension in current stable Chrome and Firefox
and record extension-menu launch, header navigation, Review bell/popover, candidate
selection and skip, library progress, agenda, settings, offline
degradation and background restart. Then run `web-ext lint` against the fresh
Firefox output and expose that check as `npm run test:firefox`.

and [Firefox built-in data consent](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).
